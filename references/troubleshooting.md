# 常见崩坏与修复

## 内容审核与更新诊断（3.2.0.7）

| 现象 | 处理 |
|---|---|
| 参考模式冲突、编辑缺视频、参考时长未知或累计超 30 秒 | 在付费前停止；检查模式和实际媒体时长。视频与音频分别累计。默认 3 段为产品注意力预算，可明确批准更高预算，仍须满足时长限制 |
| 已有远端 task_id，但新预检未通过 | 先核对属于本任务的既有任务，GET/下载恢复，不重新 POST |
| 关键内容未观察到或证据缺失 | 保留当前候选，在管理台查看实际视频和关键要求；用户作本轮内容决定。模型/Agent 不能豁免，不能自动付费重做 |
| 可通过换取景时间修复 | 先分析本地重剪，核对完整预览计划并确认；保留音轨、字幕时钟、BGM、既有费用。缓存时间线手工调整后重新预览确认，不重复旧计划 |
| 必须重新生成局部画面 | 预览有界源片、请求指纹和新增预算，再由用户确认一次原生 edit/extend。检查账号/模型/近 30 天人脸素材资格；不能接受失败原始结果或绕过完整回装 |
| 页面提示审核轮次或源片已经变化 | 刷新并重新检查当前选定候选；不得重放旧页面决定覆盖当前版本 |
| 更新目标非空或迁移内容冲突 | 停止并保留全部旧文件、暂存包与事务记录；检查配置和媒体签名，不覆盖/删除冲突内容。SQLite/WAL 由一致性快照处理 |
| 旧版发布数据缺标签、来源或指标 | 保留未知/空值；不要回填当前标签或把空指标写成 0。作品 ID 人工关联不能证明已验证上传 |

交付仍是 Skill 文件夹/ZIP，由 Agent 后台启动和更新；不新增 Windows 安装器、桌面快捷方式、任务或服务。普通用户不执行命令；不自动批准、付费或发布。

## 一、画面类

### 主角脸在第 3-4 镜后漂移
- **原因**:角色参考图权重不够,模型逐步"自由发挥"
- **修复**:
  - s3 prompt 里强制加 "严格保持参考图主角五官、发型、瞳色,不允许变化"
  - 把 character.png 分辨率提到 1024 以上,人脸占比 > 40%
  - 换用即梦"多镜头模式"——它对主体一致性优化过

### 第一镜画面太暗
- **原因**:该分镜自己的 `lighting` / `scene` 写了"黄昏""暮色"等低照度词，模型将其理解成夜晚。旧版任务也可能在 storyboard 中残留全片 `style_prefix`，但当前管线会忽略该字段
- **修复**:只修改该镜的光线描述，例如"阴天自然散射光"或"日间柔光"；不要再给全片套统一风格前缀

### 文字/招牌全是乱码
- **原因**:目前所有视频模型都画不准中文/英文
- **修复**:分镜 prompt 不要写"招牌写着 XX""书上写着 XX",改成"特写书页(不展示文字)"

### 多人同框五官全崩
- **原因**:模型同时画两张脸会塌
- **修复**:改用过肩镜头/背影/单人特写交替,避免双人正面同框

### 手部动作扭曲
- **原因**:手是 AI 视频死穴
- **修复**:prompt 不要描述"双手做 XX",改成"上半身动作""单手轻举"

## 二、合成类

### ffmpeg 报 "Non-monotonous DTS"
- **原因**:分镜间帧率/编码不一致
- **修复**:s3 生成时统一指定 fps=30;或 compose 前用 ffmpeg 先转码:
  ```
  ffmpeg -i in.mp4 -c:v libx264 -r 30 -c:a aac out.mp4
  ```

### 拼出来的画面有黑边/闪屏
- **原因**:分辨率不一致被自动缩放
- **修复**:强制每段都用 1080x1920,或合成时加 `scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920`

### 口播和画面对不上
- **原因**:单镜台词过长、提示词中同时要求第二个人声，或 2.5 原生口型偶发失配
- **修复**:先查看 `video_qa` 的 BigASR 时间轴，确认是台词内容、尾句截断还是局部嘴型偏差。局部偏差优先在母片复核中执行 Seedance 2.5 时间窗编辑；只有候选不可用且用户确认新增成本时才单条重做。4—12 秒是高密度对白建议，不是硬限制。

### BGM 比口播还响
- **原因**:`bgm_db` 默认 -14dB 不够低
- **修复**:在 `clients/ffmpeg.py:compose_final` 把 bgm_db 改成 -18 或 -20

## 三、API 类

### 429 限流
- **修复**:
  - `.env` 调低 `MAX_CONCURRENT_SHOTS=1`、`MAX_CONCURRENT_JOBS=2`
  - 保持同一 Seedance 2.5 provider，等待限流窗口恢复或在控制台申请提额；不要临时切换未验收模型
  - 火山方舟单 key QPS 默认很低,要去后台申请提额

### Seedance 任务一直 running 不结束
- **原因**:远端仍在排队/运行、轮询中断，或本地 Worker 已失联
- **修复**:在统一待办或视频任务中使用“核对远端任务”。已有 `task_id` 时系统只执行 GET 查询并恢复下载/记账，禁止直接重跑或重新 POST；只有系统确认远端没有创建任务后才允许重新入队。

### Claude 输出 JSON 解析失败
- **原因**:模型返回截断 JSON、Markdown 围栏或混入解释文字
- **修复**:系统只允许“首次生成 + 一次结构化修复”两次调用；两次都无效时以稳定错误码终止，且不会创建视频任务或 Provider 账本。不要连续手工点击生成；先缩短输入或修正结构化字段后再创建新版本。

## 四、发布类(视频号 RPA)

### 视频号上传后审核不通过
- **原因 90%**:AI 标识检测 + 敏感词
- **修复**:
  - 跑 `references/prompts/compliance.md` 复检脚本
  - 标题不要写"AI 生成"反向触发,但视频内可以加"由 AI 创作"水印满足合规
  - 涉敏词换说法:"股票" → "投资""赚钱" → "增长"

### RPA 上传失败
- 持久化 profile:`channels.weixin.qq.com` 扫码登录一次后保存 cookies
- 文件大小:控制 final.mp4 < 500MB
- 节奏:每条间隔 ≥ 30 秒,模拟真人

### 视频号 RPA 发布(参考实现路径)
1. 用 `playwright codegen https://channels.weixin.qq.com/platform` 录制扫码登录
2. 保存 storage_state.json
3. 写 publish 脚本:加载 state → 进入发布页 → 上传 mp4 → 等转码 → 填标题/话题/合集 → 点击发表
4. 加 #AI生成 标签满足平台要求
5. 多账号:每个号一个独立 profile + 独立 IP(住宅代理)

## 五、成本类

### 一条视频花了远超预期
- 看 `cli.py inspect <job_id>` 里 shots 的 `cost_cents`,定位哪一镜烧钱
- 同时核对 `provider_calls`、母片成本和任务总成本是否一致。可能已创建远端任务时不要重试；先执行任务核对。自动重试只允许明确提交前失败，质量重做必须由人工确认独立成本。

## 七、失败时该点哪个按钮

- 显示“系统正在自动恢复”：等待恢复结果，不重复点击。
- 显示“核对远端任务”：只点该动作；它不会创建新的付费任务。
- 显示“人工复核候选”：查看候选、上一版、角色和场景锚点后作质量决定。
- 显示“任务已终止”：隐私、版权、政策拒绝或人工终止不可恢复；修正输入后新建任务。
- 显示“需要人工诊断”：恢复次数已达阈值。保留数据库、任务目录和稳定错误码，不删除任务后碰运气重来。

### 想知道哪个主题 ROI 最好
- 先用 `publication-map` 绑定准确平台作品 ID，再导入 24/72/168 小时绩效快照
- 通过 `learning-report` 和预注册实验报告对比成本、完播率与线索；样本不完整时不得输出胜出结论

## 六、Skill 更新与运行时恢复

### 更新 Skill 后仍提示缺少 FFmpeg
- 先让 Agent 重新运行 `scripts/bootstrap.py --profile video --json`，确认 Skill 更新后的运行时检查结果。
- 如果公司电脑禁用了自动依赖安装，请让管理员安装 FFmpeg，并在配置中填写 `FFMPEG_PATH` 与 `FFPROBE_PATH` 的绝对路径。
- 在管理台运行环境检查中确认 FFmpeg、FFprobe 与中文字幕字体都显示可用，再开始视频生产。

### 升级失败后如何恢复
- 每次已有安装升级前，系统会在数据目录的 `backups/upgrade-<UTC时间>/` 保存 `.env`、SQLite 与角色资产快照。
- 数据库迁移或初始化失败时，Skill 初始化流程会自动恢复该快照，不需要手工复制文件。
- 成功升级后快照仍保留，可根据安装报告中的 `upgrade_backup` 路径进行人工核验；确认新版本稳定后再按磁盘策略清理旧快照。
- 使用外置 `FACTORY_DATA_DIR` 时，快照与数据库都保存在外置目录，更新 Skill 文件不会覆盖业务数据。
