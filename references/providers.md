# 生产模型与实测成本

## 主生产模型

当前生产流使用 `doubao-seedance-2-5-260628` 生成画面与口型，对白声音支持两种产品配置：默认 `seedance_native` 由 Seedance 直接合成人声；需要稳定角色音色时，`fixed_tts` 使用火山 TTS 2.0 固定声线并写回同一条原始音轨。两种模式都不串联 OmniHuman 或第三方口型模型。

| 场景 | 请求方式 | 作用 |
|---|---|---|
| 首个真人对白镜头 | 权威身份参考；`fixed_tts` 时增加 `reference_audio` | 建立人物和场景；默认由 Seedance 原生生成声音与口型 |
| 同人物、跨场景对白 | 权威身份参考 + 最近已验收角色 WAV | 身份与声线分别延续，不携带旧场景视频 |
| 同人物、同场景对白 | 权威身份参考 + 角色 WAV + 前序同场景视频 | 分别约束身份、声线和镜头轴线；人物承接上一镜结束状态，并允许按剧情走位 |
| 同人物无人脸画外音 | `reference_audio` | 延续声音，同时明确禁止人物进入 B-roll |
| 独立 B-roll / 环境镜头 | 纯提示词；有人物时仅增加必要身份参考 | 减少无关参考，保留电影化动作与环境声 |

Seedance 2.5 官方允许最多 10 段视频参考；生产默认只使用 3 段注意力预算。这个数值是产品稳定性保护，不是 Provider 能力上限。

每次请求必须先生成确定性的参考注意力清单，顺序固定为：同场景空间连续性 → 主说话人身份 → 实际出镜配角身份 → 可选声线/风格连续性。请求正文中的 `视频N / 图片N / 音频N` 必须与真实素材顺序一一对应，并明确每个素材“只负责什么、不负责什么”。重复 URI 去重但不改变优先级；必需身份超过产品注意力预算时在付费调用前停止，禁止静默丢角色。

## 真人资产发现

固定真人角色先使用火山方舟 Assets API 查询账号内资产，不读取浏览器或控制台页面。接口使用 `ark / 2024-01-01`，只检索 `GroupType=LivenessFace` 且 `Status=Active` 的资产。角色名精确且唯一时，本地保存 `asset://<assetId>`；API 无权限、无结果或多结果时，由 Agent 只向用户索要 `assetId`，再完成本地绑定。真人资产的创建与授权仍由用户在火山控制台完成。

## 计价口径

任务完成后以响应中的 `usage.completion_tokens` 和配置费率计算台账。人民币 `¥0.07 / 1,000 completion tokens` 来自历史项目观察，未核实为当前供应商价目；正式费用应核对账号账单。费用必须按 provider 调用逐笔累计；被质检拒绝、超时后完成、整镜重试等调用也是真实成本，不能只按最终成片估算。

生产预检使用 `seedance25-area-v1` 历史校准估算，并按输出画面面积调整：480p `¥0.68/秒`、720p `¥1.53/秒`、1080p `¥3.44/秒`。该口径只用于生成前预算保护，不是已核实当前资费；任务台账金额按返回 token usage 与配置费率计算，不能替代账号账单。2026-08-20 的 8 秒、720p、9:16、原生音频 R1 历史观察为 173,700 tokens / ¥12.16，预检 ¥12.24，偏差 -¥0.08（-0.7%）。

| 实测场景 | completion tokens | 成本 |
|---|---:|---:|
| 6 秒，纯提示词 / 音频引用 | 58,045 | ¥4.06 |
| 6 秒，视频引用 | 115,690 | ¥8.10 |
| 18 秒，纯提示词 | 173,335 | ¥12.13 |
| 24 秒，纯提示词 | 230,980 | ¥16.17 |
| 30 秒，纯提示词 | 288,625 | ¥20.20 |

参考素材会影响 token 数：视频引用约为同长度纯提示词或音频引用的两倍。连续真人镜头为人物一致性接受该成本；无人脸画外音只用音频引用。

管理台在用户确认生产时固化当次预估快照，成片后同时展示确认预估、实际累计和偏差。历史任务若没有确认快照，只展示实际累计并标记“历史任务未保存确认预估”，不得按当前费率倒推过去的预算判断。

管理台还会聚合已完成任务的确认快照，展示估算样本数、总体偏差与平均绝对百分比误差（MAPE）。少于 3 个有效样本时仅标记为“校准中”；达到 3 个样本后，MAPE 不高于 10% 标记为稳定，否则提示估算漂移。该指标只用于发现费率口径偏差，不自动修改单价或放宽预算门；调整 `seedance25-area-v1` 必须结合新账单样本人工评审并发布新的定价版本。

校准同时按分辨率、时长区间（4—12 / 13—24 / 25—30 秒）和参考素材类型（无参考 / 图片 / 音频 / 视频 / 混合）分组。分组样本来自用户确认时固化的逐母片预估与最终 Provider 台账；只做观察，不自动改价，也不以新算法倒算历史任务。

## 长镜头策略

- 默认开启 13—24 秒长镜头，适合完整口播和低复杂度场景。
- 25—30 秒不再硬性禁止。预检按时长、每秒台词字符数、说话人数、表演节拍和场景切换标记给出低/中/高风险；高风险需要用户单独确认后仍可生成。
- 30 秒实测可用，但出现过同音字误识别，因此仍必须经过 BigASR 精确验收。

## 局部编辑与延长

- 口型或台词局部问题使用 Seedance 2.5 `edit`：输入受控原母片与对应音频，`ratio=adaptive`、`duration=-1`，只修改指定时间窗。
- 延长母片使用 `extend`：输入受控原母片、4—30 秒延长量和明确的延续方向，原母片保持不变。
- 两类任务都请求 MOV（H.264 yuv444p + PCM）以保持编辑衔接；返回文件先落受控临时 MOV，再本地转成浏览器兼容 MP4 后执行 QA。新结果只作为候选，人工接受前不覆盖原母片。

## 并发与远端恢复

- 配置并发只是硬上限。系统持久化学习 Seedance 实际容量：明确 429 时容量减半并冷却，连续 5 个干净波次恢复 1 档；提交结果不确定时不调整容量。
- 只有依赖图同一波次、且不共享场景/人物/前序锚点的母片并发。每个波次使用独立付费批次令牌；前一波存在失败或未核对远端任务时，后续依赖波次不提交。
- 管理服务默认每 30 秒对最多 10 个已有远端任务执行一次 GET-only 核对。它只复用既有 `task_id`，不创建新任务；Windows 与阿里云均使用同一机制，不为本地控制台开放匿名公网回调。
- 可用 `PROVIDER_RECONCILE_ENABLED`、`PROVIDER_RECONCILE_INTERVAL_SEC`、`PROVIDER_RECONCILE_BATCH_SIZE` 调整开关、周期和批次。没有结构化远端 ID 的本地预留记录继续人工处置，绝不猜测或重提。

## 质量验收与重试

每条含台词母片须通过 BigASR，并检查画面、人物、场景、动作、无人脸约束及无可读文字。关键内容证据缺失、无效或不确定时保留候选并转人工内容复核，不自动付费重生；模型不能豁免。其他既有硬缺陷重试规则受次数、已确认预算及默认单次 ¥8 限制，不能绕过关键内容门。单 job 默认 ¥25 是成本提醒，超出后暂停并由用户确认新增预算，非整单硬上限。通过验收后的本地导演剪辑无新增模型费用；完整流程见 `references/workflow.md`。

## 对白声音方案与口型

`fixed_tts`：系统通过 `ListSpeakers` 读取账号可用的 TTS 2.0 声线，按角色设定确定性匹配并固化 `voice_type`。每句台词先由固定声线生成，时间戳直接用于字幕；同一音轨同时作为 Seedance 参考音频并在本地写回成片。Seedance 负责视觉和音频条件下的口型表现，不决定最终音色。

`seedance_native`：不查询声线库、不生成外挂 TTS，由 Seedance 直接合成人声。首条母片按角色设定生成；后续母片可以携带该角色最近一条已验收 WAV 延续原生音色，但跨母片一致性仍不是确定性 SLA。B-roll 在两种模式下都保留 Seedance 的环境音与物件音。

局部口型不匹配时，先核对实际源片与绑定媒体的 BigASR 时间窗，并分析本地重剪；确需新画面时才预览有界真实源片、请求指纹、尝试与新增预算。用户确认后按同一 SHA 归档源片并仅提交一次 `edit/extend`；编辑必须有视频参考，不能仅有 WAV。MOV 经受管转码与完整回装生成 MP4 候选，保留原音轨并复核关键内容；失败原始局部结果不能接受、不自动质量重试。人工接受前保留原母片和历史，不能承诺生成结果的表演/运镜必然不变。具体审核与幂等规则见 `references/workflow.md`。

## 真实 Provider R1 验证门

- 自动化验收默认只使用 MockTransport、受控本地文件和临时 SQLite，不产生任何模型费用。
- 真实 Seedance 2.5 R1 仅在用户明确授权后执行；建议使用 1 条 8 秒、720p、9:16、单场景单人物原生声画母片，单次预算上限 `¥15`。
- R1 只验证账号权限、真实排队与下载、声画输出、账单回写和管理台候选复核；不得借 R1 自动扩大到多母片、自动重试或并发压测。
- 执行前必须展示冻结预算与输入素材，执行后记录 `task_id`、实际 tokens、实际成本和质检结论；任何提交结果不确定时只核对原任务，不重新 POST。

## 真实质量基线（N0）

正式可比样本固定为 `references/quality_canary_scripts.json` 中三种形状：8 秒单人口播、18 秒双人连续场景、26 秒三人电影化场景。三条分别冻结 ¥15 / ¥30 / ¥45 的单任务上限，自动重试均为 0；每一条都必须在付费提交前单独获得用户授权，授权不能跨样本复用。

正式样本必须在首次付费调用前把完整冻结输入及其 SHA-256 指纹写入生成快照。验收时同时核对指纹、角色顺序和总时长；只满足“相同时长、相同人数”的任务仍归类为观察样本，不能进入质量对照结论。

每次真实运行把输入、参考注意力清单、Provider task ID、tokens、实际成本、镜头质检风险、人工决定和 1—5 分人工评分写入 `data/acceptance/<run-id>/acceptance.json`。缺少任一人工评分时只能标记为 `evidence_only`，不得计入三条正式基线；超出固定时长或角色数的历史成片只能标记为 `observational`。任何账号、隐私、提交结果不确定或成本异常都会停止后续样本，恢复只允许查询既有远端任务。

少于 6 个形状一致、变量一致的可比样本时，只报告方向性证据，禁止据此自动切换全局模型、锚点或声音默认值。
