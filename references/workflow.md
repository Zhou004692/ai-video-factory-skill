# 端到端生产流

## 状态机

```text
STORYBOARDED → PRODUCTION_QUEUED → PRODUCTION_RUNNING
  → ANCHOR_REVIEW_REQUIRED（可选）
  → PRODUCTION_REVIEW_REQUIRED（候选复核）
  → SHOTS_OK → BGM_OK → COMPOSED → READY_TO_PUBLISH → PUBLISHED
  ↘ PROVIDER_ACTION_REQUIRED（只核对已有远端任务，不重提）
  ↘ FAILED / REJECTED / REJECTED_PENDING_RECONCILIATION
```

每个状态都有落盘产物。中断后从数据库中的当前状态继续，禁止清空 `data/`。

## 管理台候选剧本生成与恢复

管理台确认创意角度后，新流程创建持久化生成任务并立即返回进度；每次模型请求只生成一个完整候选，目标为三版。人物、场景、对白、走位及导演字段保持完整，版本通过校验后独立保存。第三版失败不回滚前两版，页面刷新从同一任务恢复，不重复提交模型。

- 模型等待在数据库事务和业务锁外执行，其他管理台页面仍可读取。新页面使用 `background:true` 提交；旧的同步接口仅为现有调用方保留兼容。
- 来源引用只允许冻结的来源ID；简报和任务ID用于内部追溯，不作为可引用来源。字符串未结束、长度截断、错误来源引用不会被补括号后直接保存为候选。
- 每个版本的语法/契约修复次数有限，修复只处理当前版本；长度截断不自动重写整组三版。已完成版本与尚未完成版本分别记录，部分缓存不冒充完整结果。
- 模型请求结果未知或服务中断时，不自动重发。管理台明确提示可能重复产生模型费用，使用者再次确认后才能继续未知请求，且仍受次数上限限制。
- 三版保存后再进行轻量比较推荐。推荐失败不删除已完成候选，也不将默认第一版伪称为AI推荐；用户可以直接审核已有版本。
- 修改简报、来源或生成参数会隔离新旧运行；旧结果不得覆盖新修订、手动编辑的候选或已批准内容。历史合法候选保留，不因本次更新自动重新生成。
- 剧本生成任务不代表批准剧本，不自动进入视频制作；视频生成仍需原有设置和预算确认。

内部状态接口为 `GET /api/script-generation-runs/{run_id}`；继续仅由明确确认的 `POST /api/script-generation-runs/{run_id}/resume` 发起。普通使用者通过管理台操作，无需运行命令或填写内部ID。运行记录和尝试用量保存在外部业务数据库，日志不记录密钥和完整提示词。

## 自动选题抓取 MVP

```text
已授权 RSS / Atom / JSON Feed
  → 按来源周期抓取
  → 标准化与跨源去重
  → 自动选题候选池
  → 人工晋级 / 不采用
  → 内容来源与内容项目
  → 选题简报与剧本工作流
```

- 来源配置必须确认采集与使用授权，地址使用 HTTPS 且不能内嵌账号、Token、签名或密钥。
- 热点源与竞品源共用同一候选标准；竞品内容只用于事实和叙事结构参考，不复制受保护表达。
- 去重优先使用移除追踪参数后的规范 URL；无 URL 时使用标题与摘要内容指纹。合并后保留每个来源的 Feed、外部 ID、原文地址和发现时间。
- 后台线程只处理已启用、已授权且到期的来源。单个来源失败会记录安全错误和下次重试时间，不阻断其他来源。
- 候选审核和晋级均为本地零付费操作；只有晋级后的内容项目继续进入简报/剧本阶段。

## 各步骤

| 步骤 | 输入 | 产物 | 主要能力 |
|---|---|---|---|
| `s1_storyboard` | 主题、赛道、受众、目标时长 | `storyboard.json`、母片任务入库 | 按内容生成最少必要付费母片和本地导演时间线；合规和结构校验 |
| `s3_shots` | 母片、角色定妆、任务声音方案、前序锚点 | `character_identity/*`、可选 `voices/master-*`、`shots/01.mp4...`、更新后的 `storyboard.json` | `fixed_tts` 先固化火山声线并用精确音轨约束画面/口型；`seedance_native` 由 Seedance 直接合成人声；BigASR 仅做复核，视频 QA 必选 |
| `s5_bgm` | `storyboard.bgm` | `bgm.mp3` 或静音策略 | 本地音乐库 |
| `s6_compose` | 已验收母片、导演时间线、字幕、BGM | `concat.mp4`、`final.mp4` | 从母片分别取画面/原生音频，本地裁切、B-roll 覆画、字幕、混音和 CTA |
| `s7_publish` | `final.mp4` | 发布记录 | 默认人工预审并手工发布 |

## 真人角色前置解析

真人角色进入付费生产前执行：本地已绑定资产复用 → 火山 Assets API 精确唯一匹配 → 向用户索要 `assetId`。解析只接受可用的 `LivenessFace / Active` 资产，不使用浏览器兜底；无法唯一确认时停止在付费调用前。

## Seedance 镜头路由

标准版默认采用“原生母片生成 + 本地导演剪辑”，不是把所有成片镜头逐条送去生成：

1. 按叙事场景、人物连续性和音画需求生成最少必要母片；单次 Seedance 调用遵循 4—30 秒模型边界，整单不设置人为总时长上限。
2. 成片时间线按内容拆解，每段分别用 `video_master_idx` 和 `audio_master_idx` 选择画面与音频来源。
3. B-roll 段只替换画面，音频继续按时间顺序取自主体真人母片；对白母片必须从 0 秒开始连续消费到结尾，不允许漏词、重叠或重排。
4. 字幕、CTA 和 BGM 全部后期合成，不要求生成模型产出文字。hook 默认只用于营销封面；只有任务显式启用 `production_settings.hook_overlay_enabled` 时才叠加到正片。

母片内部路由仍遵循以下规则：

1. 固定真人/虚拟人像按 `asset://` 去重，同一资产即使对应多个剧本别名也只算一个人物身份。
2. AI 自动角色在任何剧情母片前默认由 Seedance 2.5 生成 4 秒无声动态身份母片，并抽取稳定帧作为可预览定妆照；后续所有母片复用同一份动态身份锚点。Seedream 5.0 静态定妆照仍作为任务级可选方案，用于效果与成本对照。
3. 自定义角色不把本地真人照片作为普通图片参考提交 Seedance，继续使用动态身份母片；失败时不进入付费场景生成。
4. 每条电影化剧情母片只解析场景文字或结构化 `cast` 中实际出现的人物，并同时携带这些人物的身份引用；不再把全剧人物注入每条镜头。
5. 身份、声线、空间三类参考正交使用：身份锚点只锁定人物，角色最近一条已验收 WAV 只延续原生声线；同一 `scene_anchor_key` 的前序母片延续同一物理场景和镜头轴线，人物空间采用 `free / continuity / locked` 三种调度模式。默认同场景相邻母片使用 `continuity`，把上一母片出镜状态传给下一母片入镜状态并允许剧情驱动的走位；一次性镜头和 B-roll 使用 `free`；只有明确正反打、局部修复等场景才使用 `locked`。同一 `site_anchor_key` 只延续项目现场的建筑语言、材质、设备与安全体系，不锁定不同子空间布局。跨场景不得为了声线复用上一条人物视频。`fixed_tts` 下每条对白携带固化音轨；`seedance_native` 下首条由 Seedance 生成对白，后续可携带该角色原生音频参考。
6. Seedance 2.5 官方允许最多 10 段视频参考；产品默认用 `SEEDANCE_PRODUCTION_REFERENCE_VIDEO_BUDGET=3` 作为注意力预算，不把官方上限当推荐用量。请求前生成参考注意力清单，按场景连续性、主说话人、配角、声线/风格排序，并把真实顺序编译成 `视频N / 图片N / 音频N` 的单一职责。超过产品预算时先拆分场景或精简参考职责，禁止静默丢弃必需人物。
7. 重复出现的同一物理场景按需生成场景锚点；不同子空间只有在明确属于同一具体项目现场时才生成更宽松的项目现场锚点。一次性场景不预生成，避免无效成本和构图锁死。
8. 独立 B-roll 母片不带声线参考；有人物出镜时仍携带必要身份锚点。身份图、动态母片和引用输入的费用都进入零付费预检与 provider 调用台账。

## 镜头验收

- 对白：BigASR 归一化后比对目标台词；数字、日期、英文缩写做 ITN 处理。
- 画面：检查人物、场景、动作、镜头稳定性和提示词遵循度。
- 场景画外音：额外检查画面无可识别人脸。
- 全部镜头：禁止生成可读文字、数字、商标或水印；字幕由合成阶段生成。
- 关键内容缺失、证据无效或未观察到要求时，保留候选进入内容人工复核，不自动产生第二次费用。其他既有硬缺陷重试规则仍受明确次数和预算保护，不能绕过关键内容人工复核。
- 只有 `visual_mismatch` 属于软偏差：保存候选并转人工复核，不自动产生第二次费用。
- `SEEDANCE_AUTO_RETRY_BUDGET_CENTS` 默认限制单次自动重试不超过 ¥8；`SEEDANCE_JOB_BUDGET_CENTS` 是单任务成本提醒值，超过后仍可经人工确认继续生成，不再作为整单硬上限。
- 对白声音由 `DIALOGUE_AUDIO_MODE` 设置全局默认，并可被单任务覆盖。产品默认 `seedance_native`；固定角色或连续母片需要稳定音色时可改为 `fixed_tts`。两者都不使用外部数字人或第三方口型模型。
- 角色锚点和重复场景锚点默认进入人工确认；只有显式设置 `anchor_review_mode=auto` 才自动放行，避免错误锚点污染后续所有付费母片。
- 内容不合格先分析本地重剪；需要新画面时才预览 `edit/extend` 和新增预算。编辑必须有视频参考，不能仅携带 WAV；MOV 经受管转码、完整回装成为 MP4 候选，保留原音轨和关键内容。失败的原始局部结果不能接受，接受前不覆盖原母片。

## 画面要求到成片的闭环

1. 批准前保存稳定编号、描述、重要级别、镜头/运镜、必须保留/允许调整项与作者指定画外音，通过冻结规格、导演 IR、编译器与 prompt 传递。此处记录意图，不宣称观察事实。
2. QA 从实际母片盲检，保存实际媒体 SHA、要求哈希和观察时间窗。关键证据缺失或无效时进入人工复核，不自动付费重试，模型不能作人工豁免。
3. 用户审核选定候选。审核轮次、候选 SHA、原接受版本及成片/发布引用防止过期或相反决定覆盖有效结果。
4. 本地重剪预览使用真实源片、冻结完整计划和绑定媒体的 ASR 缓存，并校验并发变化；确认后只改变允许的视觉时间线，保留音轨时钟、BGM 与付费图。手工修改缓存时间线后需重新预览确认；ASR 后裁切、淡入淡出和输出順序均校验关键观察时间窗保留。重复点击、重启可安全返回原动作。
5. 原生编辑预览绑定有界真实源片、请求指纹、尝试和预算。提交前按 SHA 持久归档同一源片；一次 POST 后受管转码、回装完整候选并复核。失败不会自动质量重试。接受记录绑定完整实际媒体 SHA，提交后的重复决定即使临时文件已清理也返回已记录结果；原付费节点、音频规格和历史不变。
6. 发布冻结实际成片、批准剧本、受控标签和来源；全部发布版本分别保存可空累计快照、采集时间，只有一个当前版本。当前标签修改不重写旧发布/实验证据，历史未知保持未知；关联作品不等于已验证上传或因果效果。

首尾帧与 omni 模式互斥；视频、音频参考分别累计最多 30 秒，未知时长先停止。默认 3 段视频是产品预算，明确批准 4 段仍不能超过累计时长。已有且属于本任务的付费远端任务优先 GET-only 恢复。原生含人脸编辑还依赖账号、模型与近 30 天素材资格；内部 24—60 FPS、小数时长保守容差是估算/校验口径，并非当前供应商资费保证。无新增契约旧任务保留兼容路径，不倒填批准快照。

## 长镜头

长镜头默认开启，推荐 13—24 秒。25—30 秒不会被硬性禁止；预检按时长、台词密度、说话人数、表演节拍和场景切换给出风险。高风险母片需要用户独立确认，但仍可生成；无论时长都执行相同 ASR 和视觉验收。

## 成本记录

Seedance 2.5 成本台账使用任务返回的 `usage.completion_tokens` 和项目配置的 `¥0.07 / 1,000 tokens` 计算。该费率来自历史项目观察，不代表已核实的当前供应商价目；正式费用应核对账号账单。每次 provider 调用都写入调用明细并累计到镜头和 job；失败调用及重试不能丢失。

本次 18 秒三镜干净路径实测估算：首镜纯提示词 ¥4.06、场景音频引用 ¥4.06、真人视频引用 ¥8.10，加分镜 LLM 约 ¥0.01，合计约 ¥16.23。验证过程中因被拒绝实验和重试产生的真实累计费用会更高，应与干净路径分开披露。

## 并发与失败处理

- `MAX_CONCURRENT_JOBS=4` 控制 job 并发。
- `MAX_CONCURRENT_SHOTS` / `SEEDANCE_MAX_CONCURRENT_MASTERS` 是并发上限。系统结合持久化实测容量取更小值；明确 429 自动降档，连续 5 个干净波次恢复一档。
- 同场景、同人物、共享前序音画锚点的母片按依赖波次串行；只有没有共享依赖的母片并发。每个波次使用独立付费批次，前一波存在失败或未核对任务时不启动后一波。
- 步骤异常先映射为稳定错误码，再由错误注册表决定重试、核对、人工复核或终止；界面不解析 Provider 原始报错猜动作。
- 自动重试只适用于明确发生在提交前的瞬时连接错误，并同时受次数和费用保护；已知或可能已创建远端任务时只能核对，禁止再次 POST。
- 单任务成本提醒不再是硬失败条件。超过提醒值后暂停并让用户确认新增预算；已发生费用必须保留在 Provider、母片和任务三层账本中。
- 任务恢复必须使用管理台返回的唯一下一步。不要反复点击“生成”或直接运行旧 `retry` 命令碰运气。

## 四类处置边界

| 类型 | 系统行为 | 用户动作 |
|---|---|---|
| 系统自动修复 | Worker 丢失且无远端任务时重新入队；本地 publish journal 可安全重放 | 无需操作，观察恢复结果 |
| 人工质量决定 | 有真实候选但人物、画面、口型或连续性未达标 | 接受候选、单条重做、保留上一版或终止任务 |
| Provider 核对 | 已知 `task_id`、提交结果未知或下载/落盘中断 | 只执行“核对远端任务”，不再次创建任务 |
| 不可恢复拒绝 | 隐私、版权、输出政策等确定性拒绝 | 修改输入资产或内容后创建新任务；原任务不恢复 |

当恢复连续失败达到阈值时，任务进入 `RECOVERY_REQUIRED` 和统一待办；系统保留现场，不清空产物、不自动重提付费调用。

## 远端任务主动核对

管理服务默认启动 GET-only 核对线程，每 30 秒最多处理 10 个 `PROVIDER_ACTION_REQUIRED / REJECTED_PENDING_RECONCILIATION` 中的已知远端任务。它复用现有 `task_id` 执行查询、下载、成本差额和原子发布日志，不调用任何创建任务接口；单条失败不会阻断同批后续任务。管理台展示最近核对时间和完成/进行中/失败数，并保留“立即核对”。

Windows 个人电脑与阿里云服务器都采用同一轮询恢复机制。本地管理台只绑定回环地址，不开放匿名 callback；未来云端 callback 必须先具备认证、签名校验和公网运行时隔离。
