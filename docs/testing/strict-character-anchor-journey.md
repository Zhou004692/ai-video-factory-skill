# 人物锚点正式处理器回放

状态：实现完成，独立规格审查与代码质量审查均通过。基线 `910a900`，实现提交 `bca7af1`、`085b5d9`、`fe2ae50`。

本批补齐稳定交付计划 W1/W2 的首条正式处理器链路，不代表整个内容生产流程、浏览器操作或真实视频质量已验证。

## 验收对象

真实编译与冻结图 → 临时文件 SQLite → 正式节点领取与适配器 → 正式 Seedance 请求、轮询和下载 → 正式对象存储上传 → 本地 FFmpeg 抽帧 → 真实资产落库与等待人工审核。

| 边界 | 保留内容 | 允许替换 |
|---|---|---|
| 图与状态 | 租约、冻结规格、处理器分派、事务和审核状态 | 仅临时数据库及资产路径 |
| Seedance | 提示词、参数、任务关联、解析、下载处理 | HTTPX 传输响应及明确的测试轮询等待 |
| 对象存储 | 正式 SDK、签名、HEAD、上传及响应解析 | Requests 传输响应，明确固定的时间变量 |
| 媒体 | 真正可解码的下载字节、真实本地抽帧 | 下载内容为标明来源及摘要的合成样本，不是线上生成 |
| 费用 | 正式预算和记账规则 | 假凭证、非零模拟账本，不消耗真实供应商余额 |

不能直接写入成功状态、替换业务处理器、替换 `tos.upload` 或给抽帧函数预置返回值。预置合成外部响应只能证明正式代码在该响应下的行为，不能证明供应商实际质量。

## 必须检测的失败

1. 请求提示词、角色参考、时长或任务关联发生未经认可的变化。
2. 缺少、重复或多出传输步骤；业务代码吞掉传输错误后不能使整条测试通过。
3. 下载损坏或媒体无法解码，不能仅凭供应商返回成功推导资产可用。
4. 尚未审核时重复执行，不得再次提交生成、重复记账或替换已有资产。
5. 把正式处理器换成直接返回成功的高层替身，必须被轨迹、素材和账本断言检测。
6. 未登记的网络请求、子进程、正式数据库及目录外写入，应在执行前被拒绝。

## 隔离与未覆盖

测试只使用独立进程内的临时目录、文件 SQLite 和假凭证。FFmpeg/ffprobe 仅允许已解析的本地可执行文件、指定参数和临时输入输出；不能将“允许 FFmpeg”实现为“允许任意子进程”。

标准 Python 网络/进程入口护栏与限定媒体命令，不等同于操作系统沙箱或完整进程树证明。原生扩展、Worker 子进程重启、浏览器恢复及完整母片 ASR/QA 尚需后续验证；人物定妆片本身不需要台词 QA，不能将它计入语音质量覆盖。

## 实际回放结果

正式正向路径执行了编译与冻结图、临时文件 SQLite、节点领取、`build_handlers`、人物锚点 handler、正式 Seedance 客户端、正式 TOS SDK、本地 FFmpeg 抽帧以及资产和费用落库。外部边界固定为 `POST / GET / GET / GET / HEAD / PUT` 六步；HTTPX 与 Requests 只在最终 transport 被替换。合成样本为固定摘要的 64×64、4 秒可解码 MP4，上传前后由真实 FFmpeg/ffprobe 解码并产生 JPEG 预览。

正向回放记录 7 分模拟费用，最终人物锚点为 `READY / PENDING_REVIEW`，图节点为 `REVIEW_REQUIRED`；在尚未审核时重复进入不再提交请求、重复记账或替换资产。变更提示词、参考、时长、鉴权、轮询序列、媒体摘要或处理器后，测试均在预期边界失败。整个回放使用假凭证、临时数据库和临时资产目录，实际供应商请求和费用均为 0。

本批还覆盖静态人物定妆照被供应商隐私策略拒绝后的动态替代路径。替代片必须经过 `GENERATING → 可解码 JPEG 预览 → READY / PENDING_REVIEW`，不能继承原静态定妆照的批准状态；即使项目设置为自动审核，这种身份方法变化仍需人工确认。确认后，只恢复带固定锚点等待标记且确有 `identity_reference` 依赖的未完成母片，普通母片候选不会被误批准。恢复事件绑定替代物路径和累计费用，同一对象路径被新的付费素材覆盖时仍可识别为新版本；再次执行会复用已批准替代片，不重复购买。

## 发现并修复的问题

1. 下载摘要正确但媒体不可解码时，旧实现仍可把锚点标为可审核。现改为费用和供应商证据先持久化，真实 JPEG 预览生成后才进入 `READY`；失败保持 `FAILED`、不可审核，费用不丢失。
2. 隐私策略触发的动态替代片会沿用静态定妆照的批准状态、生成器和预览，并吞掉抽帧失败。现统一使用相同的预览门禁，清理旧静态来源并强制人工审核。
3. 替代片在母片 handler 内产生时，原人物锚点节点已经成功；旧批准接口只恢复人物/场景锚点节点，导致母片永久停在 `REVIEW_REQUIRED`。现以专用、可审计且幂等的 `resume_anchor_dependency` 事件将该母片恢复为 `READY`，不是误标为母片审核通过。
4. 对象存储 URL 和本地路径可能在重新生成时保持不变。恢复事件现同时包含累计费用，避免把同路径的新付费替代片误判为已处理旧版本。

## 实施中发现的隔离缺口

在 Windows / Python 3.12 中，`asyncio.windows_utils.Popen` 继承并保留了原始 `subprocess.Popen` 类。原客户端护栏仅替换模块中的 `Popen` 名称，不能覆盖这个既有子类。独立探针将原始构造函数替换成只抛异常的哨兵，确认在护栏内仍会到达构造函数：调用 1 次、真实进程启动 0 次。

本批须补足已捕获的构造路径和异步入口验证，不能因为普通 `subprocess.Popen` 用例通过，就声明 Windows 的异步启动路径已受保护。该发现是测试隔离缺口，不是已发生在线调用的证据。

真实处理器回放复现并修复了一个产品缺陷：当下载内容与固定传输摘要一致、但实际不是可解码视频时，正式代码曾完成对象存储上传与费用记录，并在抽帧失败后把人物锚点保留为 `READY / PENDING_REVIEW`。现在损坏素材不会进入审核，已发生费用和供应商任务证据仍保留；重新下载既有供应商任务而不重复购买，仍作为后续恢复分支单独验收。

TOS SDK 构造过程还会启动 DNS 缓存线程并临时改写 urllib3 连接函数。测试须仅关闭这段 SDK 后台基础设施，保留正式签名、请求序列化、传输和响应解析，并验证没有线程或全局连接函数残留；这仍不构成操作系统级隔离证明。
