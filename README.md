# AI Video Factory

面向短视频团队的一站式 AI 内容生产工作台：从人工选题或自动抓取开始，完成来源归档、选题简报、剧本审核、角色与场景一致性控制、Seedance 2.5 原生母片生成、本地导演剪辑、成片验收、渠道发布与效果回流。

当前版本：`3.2.0.2`

当前交付方式：直接分发 Skill 文件夹或压缩包，由使用方的 Skill 更新机制同步版本。

> 产品默认通过本地管理台使用。普通用户不需要执行命令、编辑数据库或理解内部任务 ID。

## 产品定位

AI Video Factory 不是一个“输入提示词、等待单条视频”的生成器，而是一套可追溯、可审核、可恢复的内容生产系统。

它把短视频生产拆为两个层次：

- **生成层**：Seedance 2.5 按剧情和连续性边界生成最少必要的原生母片，统一产出画面、中文人声、环境音与口型。
- **导演层**：在本地完成镜头选择、节奏剪辑、字幕、B-roll、BGM、片头片尾和成片封装，减少重复模型调用。

```text
人工输入 / 授权内容源
        ↓
来源归档与解析
        ↓
选题简报与候选角度
        ↓
多版本剧本生成与人工审核
        ↓
人物定妆、场景与空间连续性锚点
        ↓
Seedance 2.5 原生母片
        ↓
BigASR 台词与字幕校准 + 画面质检
        ↓
本地导演剪辑与成片验收
        ↓
抖音 / 微信视频号发布与表现回流
```

## 核心特性

### 1. 一站式内容项目工作室

一个内容项目贯穿来源、选题、剧本、镜头、成片和发布，不再把每个阶段拆成互不关联的任务记录。

- 统一展示当前阶段、待处理事项、成本、质量与下一步动作。
- 来源、简报、剧本和生产配置均保留版本与关联关系。
- 失败任务保留技术证据，并提供可继续、可修复、可重建的恢复路径。
- 恢复入口按执行图与提交台账判定：未知提交先核对，已有候选可复核，无可执行节点时显示诊断；验证范围见 [P0 恢复闭环](docs/testing/p0-recovery-closure.md)。

### 2. 两条内容输入管线

| 输入方式 | 支持内容 | 适用场景 |
|---|---|---|
| 人工输入 | 文本、公开链接、本地视频 | 明确命题、已有素材、竞品视频分析 |
| 自动抓取 | 已授权的 RSS、Atom、JSON Feed | 热点监测、竞品内容源、定时选题 |

自动抓取结果只进入候选池，不会未经审核直接生成剧本或产生视频费用。候选经过人工确认后才转为正式内容项目。

### 3. 本地视频深度解析

针对本地视频，不只提取 ASR 台词，还会重建可供创作复用的表演与镜头信息：

- 说话人及屏幕内外关系；
- 画外音与旁白只保留音频说话人证据，不会被强制加入入镜人物或要求绑定角色资产；
- 情绪、语气、语速、音量；
- 表情、视线、手势和身体动作；
- 场景、人物站位、镜头运动与时间线；
- 原视频片段对照与人工校正。

每次新建内容项目都会形成独立解析结果，避免错误复用旧缓存污染新任务。

### 4. 可追溯的选题与剧本生成

- 简报保存来源事实底稿，创意角度不能覆盖或替代原始来源。
- 每次生成多个可比较的候选角度和剧本版本。
- 剧本保留钩子、冲突、证据、反转、解决方案和 CTA 等结构化节拍。
- 简报与剧本均支持人工二次编辑、版本保留和明确审核。
- 竞品内容只借鉴结构，不复制受保护台词、人物身份、品牌口号或表达。

### 5. Seedance 2.5 原生母片 + 本地导演剪辑

- 单条母片按内容需要规划为 `4–30 秒`，不再固定按 10 秒切片。
- 同一地点、时段、人物关系和剧情目标优先合并为连续母片。
- 跨场景、核心人物组合变化或高风险动作才建立新母片。
- 本地可从母片剪出多个节奏镜头，镜头调整不产生新的模型费用。
- B-roll 只有在补充证据、实物、流程或环境信息时才生成或复用。

### 6. 人物、场景与空间连续性

生产前会冻结人物身份和场景基线，并为每条母片选择合适的空间连续性策略：

- **人物身份锚点**：固定真人、火山虚拟人像、自定义角色或 AI 自动定妆；
- **场景锚点**：仅为跨多条母片重复出现的核心空间生成；
- **空间连续性契约**：记录服装、道具、光线、时段、180 度轴线，以及人物的起始状态、镜头内运动和结束状态。

人物站位不再全局锁死。系统根据内容自动选择以下策略：

| 空间策略 | 默认适用场景 | 约束方式 |
|---|---|---|
| `free` 自由调度 | 一次性场景、证据 B-roll、无需跨母片承接的镜头 | 保持人物身份、场景和轴线稳定；允许人物进出画、走位、换位和镜头跟随 |
| `continuity` 连续调度 | 同一场景跨多条母片延续、动作或视线需要承接 | 将上一母片的结束位置、动作趋势和轴线作为下一母片的起始状态，不固定整段构图 |
| `locked` 精确锁定 | 固定机位、证据镜头、明确指定的构图 | 锁定人物左右位置和画面布局，禁止无意换位 |

锚点支持 Seedance 2.5 与 Seedream 5.0 两种生成方案。当前默认使用 Seedance 2.5 动态锚点；生成后可在管理台“镜头 → 连续性锚点”中预览原图，并查看当前场景采用的空间策略：自由调度显示人物活动区，连续调度显示“起始状态 → 镜头运动 → 结束状态”，精确锁定才显示固定站位。确认前不会提交剧情母片。

### 7. 原生声线与可选固定声线

Graph V2 编译器与复杂度分析共用出镜/声音判断：画外对白和旁白不会仅因发声增加出镜人数，也不会默认让第一个画面人物对口型。显式安排在画面中的人物仍保留；有台词才检查台词与字幕，只有入镜对白才要求口型。纯背景音使用保留画面演员的独立执行路径，不强制人物全程闭嘴；多人同一节拍声音模式或台词归属不明确时，会提示修正模式或拆为逐人话轮，不猜测归属。规则与验证边界见 [声音与出镜语义](docs/testing/speech-visibility-contract.md)。

母片预检按冻结图中的实际依赖读取场景锚点，区分“场景身份”与“必须有参考资产”：合法单场景无锚点依赖时不会误拦；确有依赖但缺素材、生成器不匹配或未审核时仍阻断。该规则已纳入 R1 零费用门禁，见 [冻结场景依赖](docs/testing/frozen-scene-dependencies.md)。

| 模式 | 说明 | 额外配置 |
|---|---|---|
| `seedance_native` | Seedance 2.5 直接合成人声、环境音与口型，默认模式 | 无需 TTS 配置 |
| `fixed_tts` | 从火山声线库为角色匹配固定声线，再提供给 Seedance 生成表演与口型 | 需要火山 TTS 2.0 |

生成后使用 BigASR 获取真实语音时间，字幕按语义分句呈现，而不是一次性铺满整段画面。局部口型或台词问题可进入单镜修复，不必重做整条视频。

### 8. 生产可靠性与成本保护

- 每次付费提交保存唯一 Provider Task ID，恢复时只查询原任务，不重复 POST。
- 根据人物、场景和前序锚点依赖编排母片；只有无依赖母片才并发生成。
- 429 限流自动降低并发，连续稳定后再逐步恢复。
- 预算预检、任务预算、自动重试次数和单次重试预算相互独立。
- 人物身份漂移、无动机瞬移、场景漂移、台词不一致、异常文字等质量问题进入明确的人工复核节点；自由调度中的合理走位不会被误判为站位漂移。
- 自动化测试默认使用 MockTransport、临时 SQLite 和本地媒体，不产生模型费用。

### 9. 角色资产库

支持统一管理：

- 火山已授权真人资产；
- 火山虚拟人像资产；
- 多图 + 人物描述的自定义角色；
- 按剧本自动生成的 AI 角色。

角色资产支持新增、搜索、预览、启停和删除。真实人物照片不能替代火山授权真人资产；涉及真人生成时必须满足本人授权和 Provider 审核要求。

### 10. 发布与效果回流

- **抖音**：支持 OAuth 绑定和 OpenAPI 投稿，提交前仍需用户逐条确认。
- **微信视频号**：下载成片后通过官方视频号助手发布，再回填作品 ID。
- **表现回流**：支持播放、完播、互动、关注和线索等累计指标快照。
- **创意学习**：按平台、观察窗口和最低播放门槛比较钩子、叙事、证据与 CTA，不把相关性误写成因果。

## 普通用户使用方式

### Skill 分发与首次使用

1. 通过 Skill 文件夹或压缩包分发本仓库，保留 `SKILL.md`、`scripts/`、`references/` 和 `templates/`。
2. 使用方安装或更新 Skill 后，由 Agent 按 `SKILL.md` 调用 `scripts/bootstrap.py --profile script --json` 完成本地运行环境、占位配置和数据库初始化。
3. 需要管理台时，由 Agent 按宿主系统启动本地服务；Windows 使用 `scripts/open_management.ps1`，其他系统使用 Python 运行时启动 `scripts/management_server.py`。
4. Skill 更新由使用方的 Skill 更新机制完成。可替换的 Skill 目录只保存代码；`.env`、数据库、角色素材和成片保存在独立运行目录，不会被覆盖式更新删除。

更新前先关闭正在运行的管理服务，再同步新 Skill 并执行自举。升级与管理服务共用运行时互斥锁；若仍有进程占用数据，升级会停止并提示关闭服务，不会并发修改或回滚 SQLite。
5. 管理台地址：`http://127.0.0.1:8765`。

默认运行目录为 Windows 的 `%LOCALAPPDATA%\AI Video Factory`、macOS 的
`~/Library/Application Support/AI Video Factory`、Linux 的
`~/.local/state/ai-video-factory`。首次运行新版时，系统会将旧 Skill 目录内的
`.env` 与 `data/` 一次性复制到运行目录，并保留旧文件作为回退副本。可用
`FACTORY_RUNTIME_HOME` 覆盖整个运行目录，或用 `FACTORY_ENV_FILE`、
`FACTORY_DATA_DIR` 分别覆盖配置和数据路径。

### 完整生产流程

1. **创建内容项目**：输入文本、公开链接或本地视频；也可以从自动选题候选池晋级。

2. **检查来源解析**：查看原文、台词、场景、人物和表演证据；本地视频可逐片段播放并人工校正。

3. **生成选题简报**：比较候选角度，编辑受众、钩子、证据、风险和制作建议，选中唯一方向。

4. **生成并审核剧本**：设置建议总时长、分镜数和角色数；选择、编辑并审核最终剧本版本。

5. **配置视频制作**：为剧本人物绑定固定角色或选择 AI 自动生成，确认画幅、声音模式、字幕样式和预算。

6. **确认一致性锚点**：预览人物定妆和重复场景，检查每个场景采用自由调度、连续调度还是精确锁定；连续场景重点核对起始状态、镜头运动与结束状态。锚点错误时先重做锚点，不让错误参考进入付费母片。

7. **确认预算并开始生成**：系统按依赖自动调度母片，并持续同步远端任务状态、成本和质量结果。

8. **验收与局部修复**：预览母片与成片；可接受候选、局部修复、延长母片、本地重剪或单镜重做。

9. **下载或发布**：下载 MP4，或选择已配置渠道投稿；发布后登记作品和表现数据。

## 零费用技术链路回归与证据边界

开发和发布前可在**不配置任何 Provider 凭证、不产生模型费用**的前提下，检查“来源 → 简报 → 剧本 → 生产编译 → 人物/场景锚点 → 母片 → 本地导演剪辑 → 审核状态 → 待发布”的技术衔接。当前零费用旅程使用高层业务 handler 夹具和合成媒体，**不是保留全部生产 handler、仅替换 HTTP transport 的严格端到端回放，也不证明真实成片内容质量**：

```powershell
.\.venv\Scripts\python.exe tests\zero_cost_release_gate.py
```

通过时最后一行固定为：

```text
ZERO_COST_RELEASE_GATE_OK paid_provider_calls=0 external_requests=0
```

门禁分为五层并默认全部执行：

| 层级 | 覆盖范围 | 发布用途 |
|---|---|---|
| R0 | Schema、规范化、Replay fail-closed、夹具完整性 | 每次提交 |
| R1 | 生产编译器、Graph V2、导演时间线、历史事故回放 | 每次提交 |
| R2 | 高层夹具条件下的管理台写操作、编辑与锚点确认、本地合成和待发布状态 | 合并前 |
| R3 | 服务重启、租约恢复、Provider 回调边界和本地合成故障恢复 | 发布前 |
| R4 | 功能分支组合遍历、业务暂停恢复、管理台动作可达性、阻塞诊断与零费用自修复 | 发布前 |

可在开发期间只执行到某一层，例如 `python tests/zero_cost_release_gate.py --level r1`。门禁会强制使用 Replay 模式、移除子进程中的 Provider 凭证、阻止非本机网络连接，并对生产数据库与资产目录做前后内容签名；未知请求不会回退到在线模型。

### 常态化流程巡检

Flow Guard 原有四级状态继续兼容，但只描述配置技术套件：`passed` 表示套件检查满足现有断言；`partial` 表示部分必需检查跳过；`attention` 表示影子审计发现已映射处理入口的待处理任务；`failed` 表示技术检查失败或处理入口映射缺失。它们都不是“产品全部通过”或“真实任务已恢复”。人工待审核是业务等待，不等于程序故障；只读动作映射不证明恢复已执行。HTML 标题和顶部提示明确这个边界；缺少边界元数据的旧报告即使记录 `passed`，证明范围也显示 `unknown`，不能显示可信全绿。

R4 Flow Guard 不等待用户在管理台触发，也绝不修改正式任务。它在临时 SQLite 和临时媒体目录中编译 Production Spec v2、遍历 Graph V2，但 `full_flow_regression.build_zero_cost_handlers` 会替换 `character_anchor`、`scene_anchor`、`master`、`bgm` 业务 handler，直接生成夹具产物并写入状态；并非只 Mock Seedance。图调度、本地合成及若干管理服务方法仍使用正式代码，不能由此推断所有生产 handler 都执行过。回归分为三层：常态监听使用 7 条代表路径并附带 17 条历史事故回归；Smoke 使用 32 条 pairwise 组合路径；Full 从有效状态、暂停类型、故障节点、恢复动作和服务重启约束中生成 88 条可达路径，并执行配置的管理台、合成媒体金标和影子审计。无效组合不会被计入覆盖率。

Full 套件分别记录以下有限证据，不允许跨层替代：

- **夹具条件下的管理台执行链**：Playwright 点击页面，经 HTTP API 派发动作，由 Supervisor 启动隔离 Worker 子进程；分别记录 UI 派发、后端处理、Worker PID 和成功节点。Worker 中仍可能使用高层业务 handler 夹具，因此 UI/进程真实不等于生成业务 handler 全真实。
- **正式库只读影子审计**：以 SQLite `mode=ro` 和 `query_only=ON` 检查最近 100 个正式任务，同时检查任务级 `FAILED` / `BLOCKED` / 待审核状态和节点级暂停。待处理状态会映射到管理台动作；有映射的任务可使结果成为 `attention`，未知动作、空动作或缺少入口可使结果成为 `failed`。审计检查结构和入口映射，不点击入口、不恢复正式任务；不能把人工审核等待等同程序故障。审计前后验证数据库内容未被写入。
- **历史事故逐条回放**：17 条真实事故各自使用独立测试进程回放。除测试 21–25 的手势丢失、说话人未知、画外音误入镜、表演还原、故事弧和场景顺序外，还覆盖冻结母片漂移、等价付费图重绑定、候选预览缺失、本地重组恢复、远端结果与预算节点收敛，以及母片投影、镜头归属、人物/说话人、空台词、时长、依赖和 Graph 边等正式卡点。每条记录原始故障签名、检测边界、预期护栏和失败详情；语料 ID 重复或字段残缺也会在执行前直接阻断 Full 结果。
- **视频表演信息传播金标**：本地视频和图片是合成素材；ASR 文本、说话人、情绪、视觉观察和结构答案预填。它验证这些答案经过解析、归一化、绑定后能进入重建剧本，不证明从真实音视频识别这些信息的准确率。
- **媒体技术缺陷校准**：合成运动视频必须无告警；人工注入的冻结、黑帧、帧时间戳断层和音画时长错位必须 4/4 被检出。同类检查也用于零费用旅程的本地合成产物；它不判断人物一致性、口型、表演、叙事或剪辑审美。
- **证据分类账**：Graph 模拟动作、UI 实际派发、后端真实处理、Worker 节点、来源类型和 Provider 响应类型分别计数；没有证据的能力在报告中明确列为缺口，不能由其他层的覆盖率代替。

Full 套件还会执行 3 条“来源 → 简报 → 剧本 → 制作设置 → 锚点 → 母片 → 本地合成 → 待发布”服务旅程、管理台 Playwright 旅程、26 条管理台故障与处理交互场景，以及 7 组服务层动作契约。核心服务旅程关闭 ASR；最终审核中的身份、口型、字幕同步、画面完整性、干净画面和剪辑节奏检查由脚本提交 `True`，不是对产物进行真实质量验收。24 个管理台动作分别声明 UI、后端、Worker 必需证据；Full 缺少任一必需动作证据会失败。结构、语义、媒体可解码性和技术缺陷断言保留，但这些计数和 `READY_TO_PUBLISH` 状态不能证明内容质量。

报告新增 `evidence_boundaries`，逐维度记录 `status`、`source_kind`、`replacement_boundary`、`proves`、`does_not_prove` 和 `observed_checks`。当前 Flow Guard 的严格生产 handler / transport 回放、真实识别准确率、真实成片内容质量均为 `not_run`，不会因 `--suite full` 或通过标志自动升级。已知内置执行器的实际结果才能附带对应来源；自定义执行器、旧报告或结果缺失时按 `unknown` 处理。详细定义与后续证据要求见 [测试证据边界](docs/testing/assurance-boundaries.md)。

严格边界建设已包含客户端传输契约，以及人物锚点、母片到导演合成两条正式处理器旅程。`tests.test_strict_provider_boundary` 在单进程中运行真实 Seedance、豆包和 ASR HTTPX 客户端；`tests.test_strict_full_flow` 执行人物锚点链路；`tests.test_strict_master_compose_journey` 执行正式母片、视频 QA、BigASR、本地导演合成和最终审核链路。它们都只在最终 transport 回放固定响应，并阻止未登记的 socket、DNS 和子进程外逃。

人物锚点只有生成出可解码 JPEG 预览后才能进入审核；静态定妆照因隐私策略改用动态替代片时，必须重新人工确认。确认只恢复等待该锚点的未完成母片，不会批准普通母片候选，也不会重复购买替代片。

母片旅程还验证：ASR 结果按媒体 SHA 持久化并由合成阶段复用；合法空识别不会触发第二次 ASR，且会清除估算字幕；质量候选接受后不重复请求或计费；最终审核的事件、节点状态和任务投影原子提交。损坏媒体、QA/ASR 异常、合成失败、过期审核和并发相反审核均有失败回归。

可独立运行 `python -m unittest tests.test_strict_full_flow tests.test_strict_provider_boundary tests.test_strict_master_compose_journey tests.test_master_transcriptions -v`。当前尚未接入 Flow Guard Full，不覆盖 Worker 重启、浏览器或完整进程树，也不验证真实识别和内容质量，因此 Flow Guard 的整体 `strict_transport_replay` 仍保持 `not_run`。固定请求契约见 [严格传输回放说明](docs/testing/strict-transport-replay.md)，正式 handler 的状态、费用、恢复契约和未覆盖范围见 [人物锚点正式处理器回放](docs/testing/strict-character-anchor-journey.md)与[母片到导演合成正式处理器回放](docs/testing/strict-master-compose-journey.md)。

当前已完成的独立切片、真实执行边界发现的卡点及剩余接入工作，见 [稳定交付实施记录](docs/testing/stable-delivery-progress.md)。定向测试通过不等同于整个改进计划或真实视频质量已验收。

执行当前 Full 技术套件（不是所有产品功能的严格 E2E）：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py run
```

常态监听采用自适应调度：普通代码变化执行约 3–4 分钟的 Incremental 套件（7 条代表路径 + 17 条事故回放 + 正式库只读可推进性审计）；Flow Guard 自身、管理台 UI、生产图/规格/运行时等关键边界变化立即升级为 Full；即使没有关键变化，每 24 小时也会强制执行一次 Full，避免长期只依赖增量结果：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py watch
```

也可以手动执行 Incremental 或 Smoke。Incremental 用于快速复核已知卡点，Smoke 用于中型组合覆盖；发布门禁显式使用 Smoke，避免与周期 Full 重复执行浏览器旅程：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py run --suite incremental
```

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py run --suite smoke
```

每轮开始前会检查临时盘空间，默认至少保留 4 GB；系统会自动选择空间充足的本地磁盘，运行结束即删除 PID 归属的测试目录，下一轮也会回收已退出进程遗留的 `run-*` 目录。可通过 `--temp-root D:\path` 或环境变量 `AI_VIDEO_FLOW_GUARD_TEMP_ROOT` 固定临时盘。显式目录空间不足时会在生成媒体前直接失败并给出处理方法，不会继续写满系统盘。`--max-scenarios` 只用于本地快速定位，不作为正式 Full 巡检配置；代码变化检测周期默认 30 秒，完整回归周期可用 `--full-interval-hours` 调整。

每轮巡检会更新 `data/flow_guard/latest.html` 和机器报告 `latest.json`，同时保留 `latest-full.html/json` 与 `latest-incremental.html/json`，Incremental 不覆盖最近一次 Full 技术套件报告。头部列出技术范围、触发原因、跳过项、正式任务待处理数、最近 Full 基线和报告入口；机器报告还保存源码指纹，watcher 重启发现变化会强制 Full。历史 Full 时间只是调度基线，不是严格端到端或内容质量的可信验收时间。HTML 可离线打开，展示证据边界、覆盖缺口、夹具服务/管理台旅程、正式库只读动作映射、表演信息传播、媒体技术变异、历史事故和失败路径。使用 `--report data/flow_guard/custom.json` 会生成同名 HTML 及 Full/Incremental 分档文件。

报告包含执行耗时、有效路径数、唯一执行轨迹、节点类型覆盖、管理台动作覆盖、语义断言、历史变异杀伤率、服务/浏览器旅程和媒体指标。失败报告会保留可复现的场景参数、状态序列、下一步动作、节点错误和已执行修复。自动修复仅允许重建可再生投影、恢复过期本地租约、重试已修复且未付费、无远端任务、无输出产物的契约节点，并且每个节点只有一次版本化重试机会；不会提高预算、创建 Provider 任务、接受候选、改写冻结规格或删除媒体。

## 数据与安全边界

- 管理台默认只绑定本机回环地址，不对公网开放。
- 凭证保存在本地，页面只展示配置状态，不回显密钥明文。
- 来源、配置、任务、角色和媒体索引默认保存在独立的本地运行目录。
- 视频生成、自动重试和渠道投稿都需要明确的预算或发布确认。
- 本地超时不等于远端失败；系统优先核对原 Provider Task ID，禁止不确定状态下重复付费提交。
- 自动抓取只支持已授权内容源，不提供账号爬虫、浏览器模拟登录或未授权全网抓取。
- 当前交付边界是 Skill 文件夹/压缩包及其 Agent 初始化流程；Windows 安装包、桌面启动器和系统级安装注册不属于发布内容。

## 当前限制

- Seedance 生成具有模型随机性；人物、场景、口型和表演仍需经过锚点确认与人工验收。
- 视频号当前采用官方助手人工发布，不读取或托管用户 Cookie。
- 抖音直连能力依赖已审核开放平台应用与对应权限。
- 仓库当前未包含开源许可证文件；复制、再分发或商用前请先向维护者确认授权范围。

## 反馈问题

提交 Issue 时建议包含：

- 当前版本号；
- 管理台所处阶段；
- 用户可见错误信息；
- 是否发生过付费 Provider 调用；
- 可脱敏的任务时间、状态和复现步骤。

请勿在 Issue 中粘贴 API Key、Access Token、真人私有素材或完整 `.env`。
