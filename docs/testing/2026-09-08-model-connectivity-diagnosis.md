# 2026-09-08 模型连接失败诊断

本轮针对测试26持续连接失败进行只读诊断。代码基线为本地 main `f3a9d88`，时间均为北京时间。未提交生成或质检请求，未改网络配置、任务状态或重启管理服务。

## 已确认的故障层

本机到火山模型 API 和成片下载服务的 TCP 443 连接间歇超时，发生在 TLS 握手和 HTTP 请求之前。故障可在应用外复现。现有证据不能把具体责任归到本机安全软件、网关、运营商或服务端入口，也不能证明火山服务整体故障。

- Clash 留存日志中，模型 API 的超时最早见于 09:20:13，与此前测试26提交前连接失败的时段相符。09 时段有 18 条、10 时段截至 10:38:36 有 14 条相关 TCP 超时日志。
- 成片下载域名在留存日志中，10:14:28 至 10:38:05 有 13 条相关 TCP 超时，包含 Chrome 请求。留存日志不是完整业务请求台账，包含诊断流量，条数不能当成失败任务数或错误率。
- 日志明确记录 `match GeoIP(cn) using DIRECT`；失败为 `dial tcp <IP>:443: i/o timeout`。虽然 Python 继承 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:7897`，Clash 对这些目标实际使用直连。
- 三轮无鉴权 GET 对照中，绕过代理也出现连接超时。固定目标 IP、保留真实域名 SNI 并校验证书的独立 socket 探针进一步复现 TCP 超时。

## 对页面现象的解释

1. **提交前连接失败**：客户端将 ConnectError/ConnectTimeout 归为 `transient_network`。本轮 TCP 证据支持这类失败由连接阶段引起；换剧本、换角色不能解决该连接问题。
2. **已经计费但显示失败**：此前 #1 有已完成远端任务，失败位于下载阶段，随后从原任务成功取回母片。它不能被当作生成未发生，仍应核对原任务，避免重复购买。
3. **自动质检不可用**：质检也访问同一模型 API，但当前代码将多种质检异常汇总成 `qa_error`，失败记录没有完整保留原异常。网络故障是合理怀疑，不能据此断言今天每次 QA 不可用都是网络原因。
4. **后续母片等待或被阻塞**：部分属于远端结果待核对后的保护性暂停，不代表模型仍在运行。相关恢复入口和状态释放已在前两轮修复，不能替代对连接故障本身的处理。

## 处理建议与剩余定位边界

优先在另一条独立网络（例如手机热点）重跑相同只读探针，与当前 WLAN 做对照。若热点稳定而当前网络持续超时，应进一步检查当前出口和沿途网络策略；若两条独立网络均失败，再向服务方提交目标 IP、北京时间和连接阶段证据。该对照尚未执行，不能提前认定其中任一结论。

本轮未关闭 Clash、停用安全软件或修改系统 DNS：绕过代理已经失败，现有证据不足以支持这类修改。应用层后续应补齐脱敏的阶段、异常类型和底层原因记录，尤其是 QA；这属于诊断可观测性改进，不是本轮已经完成的网络修复。
