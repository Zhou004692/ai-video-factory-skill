# AI Video Factory

面向短视频团队的一站式 AI 内容生产工作台：从人工选题或自动抓取开始，完成来源归档、选题简报、剧本审核、角色与场景一致性控制、Seedance 2.5 原生母片生成、本地导演剪辑、成片验收、渠道发布与效果回流。

当前版本：`3.2.0.0`

当前正式支持：Windows 个人 PC 单机版

> 产品默认通过本地管理台使用。普通用户不需要执行命令、编辑数据库或理解内部任务 ID。

## 产品定位

AI Video Factory 不是一个“输入提示词、等待单条视频”的生成器，而是一套可追溯、可审核、可恢复的内容生产系统。

它把短视频生产拆为两个层次：

- **生成层**：Seedance 2.5 按剧情和连续性边界生成最少必要的原生母片，统一产出画面、中文人声、环境音与口型。
- **导演层**：在本地完成镜头选择、节奏剪辑、字幕、B-roll、BGM、片头片尾和成片封装，减少重复模型调用。

```text
人工输入 / 授权内容源
        ↓
来源归档与解析
        ↓
选题简报与候选角度
        ↓
多版本剧本生成与人工审核
        ↓
人物定妆、场景与空间连续性锚点
        ↓
Seedance 2.5 原生母片
        ↓
BigASR 台词与字幕校准 + 画面质检
        ↓
本地导演剪辑与成片验收
        ↓
抖音 / 微信视频号发布与表现回流
```

## 核心特性

### 1. 一站式内容项目工作室

一个内容项目贯穿来源、选题、剧本、镜头、成片和发布，不再把每个阶段拆成互不关联的任务记录。

- 统一展示当前阶段、待处理事项、成本、质量与下一步动作。
- 来源、简报、剧本和生产配置均保留版本与关联关系。
- 失败任务保留技术证据，并提供可继续、可修复、可重建的恢复路径。

### 2. 两条内容输入管线

| 输入方式 | 支持内容 | 适用场景 |
|---|---|---|
| 人工输入 | 文本、公开链接、本地视频 | 明确命题、已有素材、竞品视频分析 |
| 自动抓取 | 已授权的 RSS、Atom、JSON Feed | 热点监测、竞品内容源、定时选题 |

自动抓取结果只进入候选池，不会未经审核直接生成剧本或产生视频费用。候选经过人工确认后才转为正式内容项目。

### 3. 本地视频深度解析

针对本地视频，不只提取 ASR 台词，还会重建可供创作复用的表演与镜头信息：

- 说话人及屏幕内外关系；
- 画外音与旁白只保留音频说话人证据，不会被强制加入入镜人物或要求绑定角色资产；
- 情绪、语气、语速、音量；
- 表情、视线、手势和身体动作；
- 场景、人物站位、镜头运动与时间线；
- 原视频片段对照与人工校正。

每次新建内容项目都会形成独立解析结果，避免错误复用旧缓存污染新任务。

### 4. 可追溯的选题与剧本生成

- 简报保存来源事实底稿，创意角度不能覆盖或替代原始来源。
- 每次生成多个可比较的候选角度和剧本版本。
- 剧本保留钩子、冲突、证据、反转、解决方案和 CTA 等结构化节拍。
- 简报与剧本均支持人工二次编辑、版本保留和明确审核。
- 竞品内容只借鉴结构，不复制受保护台词、人物身份、品牌口号或表达。

### 5. Seedance 2.5 原生母片 + 本地导演剪辑

- 单条母片按内容需要规划为 `4–30 秒`，不再固定按 10 秒切片。
- 同一地点、时段、人物关系和剧情目标优先合并为连续母片。
- 跨场景、核心人物组合变化或高风险动作才建立新母片。
- 本地可从母片剪出多个节奏镜头，镜头调整不产生新的模型费用。
- B-roll 只有在补充证据、实物、流程或环境信息时才生成或复用。

### 6. 人物、场景与空间连续性

生产前会冻结人物身份和场景基线，并为每条母片选择合适的空间连续性策略：

- **人物身份锚点**：固定真人、火山虚拟人像、自定义角色或 AI 自动定妆；
- **场景锚点**：仅为跨多条母片重复出现的核心空间生成；
- **空间连续性契约**：记录服装、道具、光线、时段、180 度轴线，以及人物的起始状态、镜头内运动和结束状态。

人物站位不再全局锁死。系统根据内容自动选择以下策略：

| 空间策略 | 默认适用场景 | 约束方式 |
|---|---|---|
| `free` 自由调度 | 一次性场景、证据 B-roll、无需跨母片承接的镜头 | 保持人物身份、场景和轴线稳定；允许人物进出画、走位、换位和镜头跟随 |
| `continuity` 连续调度 | 同一场景跨多条母片延续、动作或视线需要承接 | 将上一母片的结束位置、动作趋势和轴线作为下一母片的起始状态，不固定整段构图 |
| `locked` 精确锁定 | 固定机位、证据镜头、明确指定的构图 | 锁定人物左右位置和画面布局，禁止无意换位 |

锚点支持 Seedance 2.5 与 Seedream 5.0 两种生成方案。当前默认使用 Seedance 2.5 动态锚点；生成后可在管理台“镜头 → 连续性锚点”中预览原图，并查看当前场景采用的空间策略：自由调度显示人物活动区，连续调度显示“起始状态 → 镜头运动 → 结束状态”，精确锁定才显示固定站位。确认前不会提交剧情母片。

### 7. 原生声线与可选固定声线

| 模式 | 说明 | 额外配置 |
|---|---|---|
| `seedance_native` | Seedance 2.5 直接合成人声、环境音与口型，默认模式 | 无需 TTS 配置 |
| `fixed_tts` | 从火山声线库为角色匹配固定声线，再提供给 Seedance 生成表演与口型 | 需要火山 TTS 2.0 |

生成后使用 BigASR 获取真实语音时间，字幕按语义分句呈现，而不是一次性铺满整段画面。局部口型或台词问题可进入单镜修复，不必重做整条视频。

### 8. 生产可靠性与成本保护

- 每次付费提交保存唯一 Provider Task ID，恢复时只查询原任务，不重复 POST。
- 根据人物、场景和前序锚点依赖编排母片；只有无依赖母片才并发生成。
- 429 限流自动降低并发，连续稳定后再逐步恢复。
- 预算预检、任务预算、自动重试次数和单次重试预算相互独立。
- 人物身份漂移、无动机瞬移、场景漂移、台词不一致、异常文字等质量问题进入明确的人工复核节点；自由调度中的合理走位不会被误判为站位漂移。
- 自动化测试默认使用 MockTransport、临时 SQLite 和本地媒体，不产生模型费用。

### 9. 角色资产库

支持统一管理：

- 火山已授权真人资产；
- 火山虚拟人像资产；
- 多图 + 人物描述的自定义角色；
- 按剧本自动生成的 AI 角色。

角色资产支持新增、搜索、预览、启停和删除。真实人物照片不能替代火山授权真人资产；涉及真人生成时必须满足本人授权和 Provider 审核要求。

### 10. 发布与效果回流

- **抖音**：支持 OAuth 绑定和 OpenAPI 投稿，提交前仍需用户逐条确认。
- **微信视频号**：下载成片后通过官方视频号助手发布，再回填作品 ID。
- **表现回流**：支持播放、完播、互动、关注和线索等累计指标快照。
- **创意学习**：按平台、观察窗口和最低播放门槛比较钩子、叙事、证据与 CTA，不把相关性误写成因果。

## 普通用户使用方式

### 首次安装

1. 下载或克隆本仓库。
2. Windows 用户双击根目录的 **`安装 AI 视频工厂.cmd`**。
3. 安装器会自动准备 Python 隔离环境、依赖、FFmpeg、SQLite，并在 Windows 桌面放置可见的 **`AI Video Factory.cmd`** 启动脚本。
4. 安装完成后直接双击桌面启动脚本；也可以运行 Skill 根目录的 **`打开 AI 视频工厂.cmd`**，或对已安装本 Skill 的 Agent 说：**“打开 AI 视频工厂”**。
5. 浏览器打开本地管理台：`http://127.0.0.1:8765`。

已有 `.env`、数据库、角色资产和业务数据不会被初始化过程覆盖。
启动脚本只是一个可查看、可复制、可删除的普通文件，不注册计划任务、不安装 Windows 服务、不写注册表。它会先检查服务状态：服务已运行时只打开管理台；未运行时在后台静默启动，等待就绪后再打开浏览器，重复点击不会启动多个服务。启动日志位于 `%LOCALAPPDATA%\AI Video Factory\logs`。

### 完整生产流程

1. **创建内容项目**：输入文本、公开链接或本地视频；也可以从自动选题候选池晋级。

2. **检查来源解析**：查看原文、台词、场景、人物和表演证据；本地视频可逐片段播放并人工校正。

3. **生成选题简报**：比较候选角度，编辑受众、钩子、证据、风险和制作建议，选中唯一方向。

4. **生成并审核剧本**：设置建议总时长、分镜数和角色数；选择、编辑并审核最终剧本版本。

5. **配置视频制作**：为剧本人物绑定固定角色或选择 AI 自动生成，确认画幅、声音模式、字幕样式和预算。

6. **确认一致性锚点**：预览人物定妆和重复场景，检查每个场景采用自由调度、连续调度还是精确锁定；连续场景重点核对起始状态、镜头运动与结束状态。锚点错误时先重做锚点，不让错误参考进入付费母片。

7. **确认预算并开始生成**：系统按依赖自动调度母片，并持续同步远端任务状态、成本和质量结果。

8. **验收与局部修复**：预览母片与成片；可接受候选、局部修复、延长母片、本地重剪或单镜重做。

9. **下载或发布**：下载 MP4，或选择已配置渠道投稿；发布后登记作品和表现数据。

## 配置要求

管理台会按所用能力提示缺失配置，不要求首次一次性配齐。

| 能力 | 必要配置 | 影响 |
|---|---|---|
| 只做来源、简报和剧本 | `ARK_API_KEY` | 豆包 LLM 生成与分析；使用 Claude 时另配 `ANTHROPIC_API_KEY` |
| 生成 Seedance 视频 | `ARK_API_KEY` | Seedance 2.5、视觉理解和质量检查 |
| 本地视频解析、字幕和台词验收 | `VOLC_ASR_API_KEY` | 录音文件识别 2.0 / BigASR |
| 视频质检与连续镜头引用 | `VOLC_AK`、`VOLC_SK`、`TOS_BUCKET` | 上传受控媒体供模型访问；同时用于授权角色资产发现 |
| 固定角色声线 | `VOLC_TTS_APPID`、`VOLC_TTS_API_KEY` | 仅 `fixed_tts` 模式需要 |
| 抖音直连发布 | `DOUYIN_CLIENT_KEY`、`DOUYIN_CLIENT_SECRET`、`DOUYIN_REDIRECT_URI` | OAuth 绑定与 OpenAPI 投稿 |

完整字段和默认值见 [templates/env.example](templates/env.example)。普通用户应优先在管理台“配置中心”填写，不需要手工编辑 `.env`。

## 零费用全链路回归

开发和发布前可在**不配置任何 Provider 凭证、不产生模型费用**的前提下，验证“来源 → 简报 → 剧本 → 生产编译 → 人物/场景锚点 → 母片 → 本地导演剪辑 → 成片验收 → 待发布”主链路：

```powershell
.\.venv\Scripts\python.exe tests\zero_cost_release_gate.py
```

通过时最后一行固定为：

```text
ZERO_COST_RELEASE_GATE_OK paid_provider_calls=0 external_requests=0
```

门禁分为五层并默认全部执行：

| 层级 | 覆盖范围 | 发布用途 |
|---|---|---|
| R0 | Schema、规范化、Replay fail-closed、夹具完整性 | 每次提交 |
| R1 | 生产编译器、Graph V2、导演时间线、历史事故回放 | 每次提交 |
| R2 | 管理台真实写操作全流程、人工编辑与锚点确认、成片和待发布 | 合并前 |
| R3 | 服务重启、租约恢复、Provider 回调边界和本地合成故障恢复 | 发布前 |
| R4 | 功能分支组合遍历、业务暂停恢复、管理台动作可达性、阻塞诊断与零费用自修复 | 发布前 |

可在开发期间只执行到某一层，例如 `python tests/zero_cost_release_gate.py --level r1`。门禁会强制使用 Replay 模式、移除子进程中的 Provider 凭证、阻止非本机网络连接，并对生产数据库与资产目录做前后内容签名；未知请求不会回退到在线模型。

### 常态化流程巡检

R4 Flow Guard 不读取用户任务，也不等待用户在管理台触发。它在临时 SQLite 和临时媒体目录中编译真实 Production Spec v2、遍历真实 Graph V2，并只用 Seedance 2.5 Mock 生成本地测试母片。默认 Full 套件不是固定抽取若干 pairwise 用例，而是从有效状态、暂停类型、故障节点、恢复动作和服务重启约束中生成 88 条可达路径；无效组合不会被计入覆盖率。

Full 套件还会执行 3 条“来源 → 简报 → 剧本 → 制作设置 → 锚点 → 母片 → 本地合成 → 待发布”服务旅程、1 条真实管理台 Playwright 全流程和 11 条管理台故障处置场景。每轮同时运行 9 类历史故障变异校准，并独立检查母片投影、镜头归属、人物/说话人引用、台词、时长、依赖边、最终媒体可解码性。成功标准是语义断言全部通过、历史故障杀伤率不低于 95%、无付费调用，而不是单看场景数量。

完整遍历全部功能分支：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py run
```

常态运行默认监听相关代码，发生变更后自动执行 Full 套件：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py watch
```

开发调试时使用 Smoke 套件获得快速反馈；发布门禁也显式使用 Smoke，避免与常态 Full 巡检重复执行浏览器旅程：

```powershell
.\.venv\Scripts\python.exe scripts\flow_guard.py run --suite smoke --max-scenarios 8
```

`--max-scenarios` 只用于本地快速定位，不作为正式 Full 巡检配置。代码变化检测周期默认为 30 秒。

最新机器可读报告默认写入 `data/flow_guard/latest.json`。报告包含执行耗时、有效路径数、唯一执行轨迹、节点类型覆盖、管理台动作覆盖、语义断言、历史变异杀伤率、服务/浏览器旅程和媒体指标。失败报告会保留可复现的场景参数、状态序列、下一步动作、节点错误和已执行修复。自动修复仅允许重建可再生投影、恢复过期本地租约、重试已修复且未付费、无远端任务、无输出产物的契约节点，并且每个节点只有一次版本化重试机会；不会提高预算、创建 Provider 任务、接受候选、改写冻结规格或删除媒体。

## 数据与安全边界

- 管理台默认只绑定本机回环地址，不对公网开放。
- 凭证保存在本地，页面只展示配置状态，不回显密钥明文。
- 来源、配置、任务、角色和媒体索引默认保存在本地 `data/`。
- 视频生成、自动重试和渠道投稿都需要明确的预算或发布确认。
- 本地超时不等于远端失败；系统优先核对原 Provider Task ID，禁止不确定状态下重复付费提交。
- 自动抓取只支持已授权内容源，不提供账号爬虫、浏览器模拟登录或未授权全网抓取。
- 当前正式验收范围为 Windows 个人 PC；服务器部署尚未纳入当前发布范围。

## 当前限制

- Seedance 生成具有模型随机性；人物、场景、口型和表演仍需经过锚点确认与人工验收。
- 视频号当前采用官方助手人工发布，不读取或托管用户 Cookie。
- 抖音直连能力依赖已审核开放平台应用与对应权限。
- 仓库当前未包含开源许可证文件；复制、再分发或商用前请先向维护者确认授权范围。

## 反馈问题

提交 Issue 时建议包含：

- 当前版本号；
- 管理台所处阶段；
- 用户可见错误信息；
- 是否发生过付费 Provider 调用；
- 可脱敏的任务时间、状态和复现步骤。

请勿在 Issue 中粘贴 API Key、Access Token、真人私有素材或完整 `.env`。
