# 声音与出镜语义

范围：CreativeIR、Graph V2 编译器、复杂度分析、母片执行分派与语音质检参数。本次统一这些消费者的判断，不重写历史付费规格、不生成新视频，也不证明实际成片口型或表演已达标。

## 规则

| 创作输入 | 画面人物 | 母片入镜说话人 / 口型 | 保留的声音信息 |
|---|---|---|---|
| 入镜对白，台词非空 | 显式画面人物，加上入镜说话人 | 入镜说话人，要求口型 | 台词、音频说话人、表演字段 |
| 工人入镜，客户画外说话 | 仅显式画面人物；不自动增加客户 | 不把工人填成说话人，不要求其对口型 | 客户画外台词及台词/字幕检查 |
| 旁白配画面 | 仅显式画面人物 | 不因旁白要求口型 | 旁白及台词/字幕检查 |
| 同一人物显式可见，但当前声音模式为画外 | 保留该画面人物 | 不凭“可见”推断正在说话 | 原声音模式与台词 |
| 无台词 | 保留显式人物及明确的出镜关系 | 不增加口型要求，不用第一个人物伪造发言 | 动作、情绪、镜头意图等原字段 |

声音模式缺失时，按每个说话人的既有命名线索分别推断；显式合法的 `on_screen` / `off_screen` / `narration` 优先。复杂度与编译器不能分别维护不同的 cast 计算方式。

一个未拆分节拍同时包含不同声音模式，无法可靠决定哪段台词属于谁：编译应给出可修正问题，要求拆分逐话轮节拍或明确统一模式，不按第一个说话人决定其余人。非法的显式模式也应明确提示；合法画外说话人不要求加入画面人物表，但未知的入镜人物仍需修正。

统一声音模式不等于已经标明台词归属。同一节拍声明多个画外声音，却只有一句未分配给具体人的台词时，应提示拆分逐人话轮；不能默认为第一人，也不能擅自改成齐声。已有逐人节拍不受影响。

明确声明 `on_screen` 且有台词，却缺少说话人时，应提示补充说话人；不能把入镜对白降成画外音，也不能用首个画面人物兜底。

从已有母片读取表演节拍时，母片级声音模式作为缺省值传递给节拍，节拍自己的显式模式可覆盖它。编译后的 `audio_speakers` 与表演节拍保留原发声身份；入镜 `speaker_ids` 不再以首个 cast 兜底。

## 执行与质检

纯画外对白或旁白母片使用独立的 `background_voiceover` 执行路径：画面保持显式人物与身份参考，声音保持原台词和逐节拍表演要求，不伪造入镜说话人。它不同于既有禁止人物面部的 `scene` 场景画外音路径；既有路径保持兼容。

画外语音不要求人物对口型，但不意味着人物必须全程闭嘴。明确的惊讶张嘴、呼吸、表情和无声反应应保留，不能被通用背景音模板覆盖。

`expect_speech` 与 `require_lip_sync` 分开：画外语音仍要按原配置检查转写文本与预期台词的相似度及其他画面约束，但不因为没有同步嘴型而判失败。原始口型观察证据仍保留。后者默认 `true`，既有调用不因此自动取消口型检查。

注意：现有执行器在 ASR 合并后把 `raw.confidence` 设为 `1.0`，因此本轮不能宣称已验证真实转写置信度；本补丁也不证明识别准确率。该既有证据口径问题需另行处理。

有真实入镜对白的混合母片仍走入镜对白路径；重编译时新增入镜对白不能沿用旧的纯背景音路径。锚点人工审核和预算规则不因声音模式而跳过。

## 创意与兼容

多人风险建议以身份、轴线、活动路径和动作衔接为重点，不一律要求固定站位。既有自由调度、连续调度、精确锁定策略保持原职责；是否锁定由内容和用户要求决定。

本改动仅影响后续编译的派生语义，不迁移数据库、不替换已确认/已付费母片、不追加预算或调用 Provider。导演时间线、镜头归属、角色/场景锚点和表演字段仍需通过相邻回归。

## 回归入口

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_creative_ir tests.test_production_complexity tests.test_production_compiler -v
.\.venv\Scripts\python.exe -m unittest tests.test_video_upgrade.VideoQATests tests.test_scene_voiceover tests.test_character_voices -v
```

已知失败样例：工人检查设备、客户画外确认。旧逻辑把 1 个画面人物计为 2 人，并计入 1 项口型需求；正确结果为画面 1 人、口型需求 0，客户台词保留。

共享规则测试证明判断一致；`RuntimeSpeechDispatchTests` 进一步执行真实编译、临时数据库物化、锚点读取/审核及母片分派，在最终生成边界截获请求，检查人物参考和画外台词没有丢失。锚点是预置测试资产，未执行完整模型生成、下载与媒体质量验收，不能把它算作严格传输全旅程。

正式 handler 完整执行、管理台恢复及真实内容效果仍需分别提供对应证据，不能由这些用例通过推导出来。
