# P0 恢复闭环实施与验收

基线：`5ab3b38`。范围：图状态操作、复核重做及重启一致性、恢复分类、页面与命令共用动作判定。P1 的请求预检和完整传输诊断另行推进。

实施顺序：

1. 集中节点完成操作：在同一事务提交事件、结果、下一步与租约释放；保留处理器完成检查点，拒绝失效租约回写。
2. 集中业务投影与恢复判定：人工终止优先；运行中不重入；未知远端任务只核对；候选先复核；明确未提交失败才重试；无可执行节点显示诊断原因。
3. 管理台读取和命令执行共用上述判定；复核、重做与恢复同步执行图，不清除历史付费证据。
4. 验证节点事务中断、处理器完成后退出、混合候选决定、远端未核对与网络失败组合、过期页面及终止竞争；运行相关回归并保存证据。

验收边界：使用隔离数据库与固定 Provider 响应，不调用付费生成；进程级恢复需独立进程证据，不能以单进程 mock 代替。正式素材、任务和预算保持原状。实现结果及未通过项在本文件补录。

## 已实现（2026-09-08）

- `finish_attempt` 一次提交节点事件、结果、错误、下一步和租约释放；重复事件不重复落库，旧租约不能覆盖新尝试。处理器完成检查点独立持久化，提交过程中退出可在新进程重放。
- 过期节点先核对提交台账：没有远端 ID 的提交预留也算未核对；付费记录、候选和损坏检查点不能被当作未生成直接重试。人工终止或已发布任务不能领取新节点、预留新付费提交或被投影恢复为生成状态。
- 图执行结束与监督恢复共用受事务保护的投影，状态变化写入审计事件。仅剩等待节点时进入恢复诊断，不显示虚假的排队状态。
- `recovery_plan` 统一 Graph V2 的继续生成、网络重试、候选复核与阻塞提示。执行命令时重新核对当前状态；可继续的执行图不再依赖旧接口的账号错误码。
- 候选决定保留其他母片的失败、预算阻塞和远端待核对记录。未知提交期间允许接受已有候选，暂不允许重做；缺候选文件显示诊断。UI 使用返回的复核资格和决定列表，轮询比较包含恢复动作变化。
- 原有单条重做的执行图同步、复核操作日志及启动恢复继续保留；本次没有重写视频处理器、Provider 传输或专门的局部编辑流程。
