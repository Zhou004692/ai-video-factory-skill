## W3 声音与出镜规则：独立审查已通过

`d1a2cf4` 已将 IR、复杂度和编译器的出镜/声音/口型判断统一，保留画外台词和显式画面人物，移除虚构的入镜说话人。逐话轮继承、非法/歧义模式、静默和空白拆片已补回归；不普遍要求固定站位。

代码审查随后在真实编译、临时数据库物化及 `s3_shots.run` 分派中复现：纯画外音生成了空的入镜说话人，但仍使用要求入镜说话人的路径，触发 `shot #1 speaker  not found`。这是原字段测试未覆盖的执行边界，已在 `370ca21` 补齐保留可见演员的背景音执行路径及独立口型检查开关。

修复保留显式演员和身份参考，不将画外声重新绑定到画面人物；按原配置检查台词文本，但不要求画外声对口型。既有 `scene` 路径明确禁止人物面部，不能简单切换过去而丢掉画面演员。

后续审查还发现并修复：

- `d0cc46e`：移除“全程闭嘴”与明确表演之间的冲突；多个背景声音缺少逐人台词归属时，在生成前给出 `speech_turn_ambiguous`，不静默遗漏第二人。
- `f8c2d58`：明确入镜对白却缺少说话人时给出 `speaker_missing`，不将其降为背景音。

上述修正均先由失败用例复现，再完成独立需求和代码复审。真实请求边界测试仍截获最终生成调用，不能算作完整付费 handler 传输旅程或真实视频效果验收。

## 真实处理器边界新发现

### 单场景身份与锚点依赖混淆（已修复，独立审查通过）

输入：8 秒、画面工人检查设备、客户画外确认。编译结果 `mode=stable`，没有 `scene_anchor` 节点，但 runtime master 仍有 `scene_anchor_key`。实际 `s3_shots.run` 将所有此类 key 作为必需资产，再以 `existing_only=True` 读取，因此触发：

```text
frozen scene anchor is not ready: scene:7ae4b7c7678e
```

最初使用内存 SQLite 和真实预检复现；持久回归进一步执行真实编译 → 临时文件 SQLite 物化 → 冻结适配器 → 真实预检，同样先得到上述错误。

`d1339a2` 已让执行器遵从冻结图中的实际场景依赖：显式空集与旧调用 `None` 分开，非法依赖、缺资产、生成器不匹配和未审核仍阻断；场景身份、人物参考、预算及原有全任务审核门保留。原例修复后到达最终生成请求边界，未生成或上传真实资产。规则见 [冻结场景依赖](frozen-scene-dependencies.md)。

独立规格审查与代码质量审查均通过，各自复跑场景依赖与适配器组合 33 项。规格审查在独立进程加载旧版真实模块，复现同例失败后核对新版通过；质量审查另核对 4 个现有编译样例、5 个母片的依赖传递。均未修改正式任务或调用在线生成。

兼容性只读检查：默认本地库中 5 个 Graph V2 任务的 11 条母片规格通过新增依赖解析。只读取冻结规格，未执行任务、校验素材内容或修改任何正式状态，不能据此声称历史任务恢复成功。

### W1/W2 首条正式处理器旅程：人物锚点

`bca7af1` 已建立首条人物锚点正式处理器回放：真实编译与冻结图 → 临时文件 SQLite → 节点领取及正式 handler → Seedance 提交/轮询/下载 → TOS SDK 签名、HEAD 与上传 → 本地 FFmpeg 抽帧 → 资产、7 分模拟费用与人工审核暂停。固定回放为六个传输步骤；请求结构、媒体摘要、状态、账本和重复进入均有断言。测试期间实际外部请求及供应商费用为 0。

回放先发现“摘要正确但不可解码的下载仍进入审核”，并在同一提交中修复为只有真实 JPEG 预览生成成功后才可 `READY`；失败费用和供应商证据保留。Windows 捕获的 `asyncio.windows_utils.Popen` 路径也纳入子进程护栏，TOS 仅关闭测试期 DNS 缓存线程，正式签名和响应处理未替换。

质量审查进一步发现静态定妆照隐私拒绝后的动态替代路径绕过上述门禁。`085b5d9` 统一替代片预览状态机，清除旧批准/静态溯源，强制人工确认，并用固定错误码区分锚点待审与普通母片候选。批准接口只将确有身份依赖的未完成母片通过专用事件恢复为 `READY`；批准后复用替代片，不重复购买。`fe2ae50` 再将累计费用纳入替代物事件标识，覆盖对象 URL/路径不变但出现新付费素材的情况。

独立规格审查与代码质量审查均通过，未发现待合并的阻塞问题。根代理已在移除 Provider 凭证的环境运行关键组合 61 项及扩大组合 661 项，均通过。详细契约、缺陷和限制见 [人物锚点正式处理器回放](strict-character-anchor-journey.md)。

人物锚点旅程本身不改变 Flow Guard Full 的整体 `strict_transport_replay=not_run`。当时尚未覆盖母片候选、ASR/QA 和完整本地合成；这些边界现由下一节的独立旅程补齐，但 Worker 重启、浏览器确认、跨进程历史任务恢复和真实视频质量仍未形成同等级证据。损坏媒体基于既有供应商任务的无重复购买重新下载也仍待实现。

### W2 母片到导演合成正式处理器旅程

`c825edc`、`ea61ae7`、`7d27ca1`、`9ca049f` 建立了第二条正式处理器回放：真实编译/冻结图、节点领取、正式母片 handler、Seedance 与 TOS、豆包视频 QA、BigASR、媒体 SHA 绑定派生产物、本地导演剪辑、无声 BGM 和最终审核。正常链路固定 11 个传输步骤、一次 Seedance 付费提交、一次 ASR 提交和 7 分模拟费用；实际在线请求与供应商费用为 0。

独立审查在原本通过的旅程中继续发现并修复三类正式卡点：ASR 只保存在可变 storyboard 导致合成阶段二次识别；最终审核可在过期/失败节点上写出成功事件并返回解锁；ASR 合法空结果未持久化且残留估算字幕。现改为派生产物按媒体 SHA 绑定，合法空结果与缺失/损坏明确区分，最终审核的复核、事件、节点状态和任务投影在同一写事务中提交。

回归还覆盖 QA/ASR transport 失败、候选接受、损坏下载、合成失败、重复进入、并发相反审核、派生产物多版本和损坏缓存隔离。独立规格审查与代码质量审查均通过；质量复审另运行关键 13 项与扩大组合 357 项，并将并发相反终审连续验证 5 次，未发现待合入的阻塞问题。详细契约与限制见 [母片到导演合成正式处理器回放](strict-master-compose-journey.md)。

提交 `9ca049f` 上，根代理移除 Provider 凭证后运行母片旅程、派生产物与管理 API 定向组合 28 项，通过（72.614 秒）；R0 22 项、R1 68 项通过，记录 `paid_provider_calls=0`、`external_requests=0`、`invariant_issues=0`。随后全量 1615 项通过（805.742 秒，跳过 1 项）；内含零费用 Flow Guard 增量巡检通过并保持 `strict_transport_replay=not_run`、`recognition_accuracy=not_run`、`actual_content_quality=not_run` 的证据边界。

这条旅程补齐了单进程母片/QA/ASR/本地合成的严格边界，但尚未接入 Flow Guard Full 的内置证据来源，也未覆盖浏览器、Supervisor/Worker 进程树、跨进程重启和真实 Provider。因此整体 `strict_transport_replay` 仍为 `not_run`，真实识别准确率和内容质量仍为 `not_run`。

### 后续需处理的既有证据口径

执行器的 ASR 合并路径会将 `raw.confidence` 固定为 `1.0`。本轮保留台词文本相似度检查，但不把该固定值当作真实识别置信度。后续质量证据改进需区分真实观测值、兼容默认值和未知值，并补独立样本；本轮没有擅自变更生产 QA 阈值。
