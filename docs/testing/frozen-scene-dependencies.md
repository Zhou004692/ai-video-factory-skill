# 冻结图中的场景锚点依赖

## 故障与目标

单场景 `stable` 任务可合法不生成场景锚点，编译后的母片仍保留 `scene_anchor_key` 作为场景身份。旧执行器把这个身份字段当作必须存在的资产，在 `prepare_anchors=False` 时抛出 `frozen scene anchor is not ready`，即使冻结图根本没有对应锚点节点。

修复目标：母片执行以冻结生产图中的实际 `scene_reference` 依赖为准，不通过清空场景身份、额外生成付费锚点或伪造审核状态消除错误。

## 边界约定

- Graph V2 适配器从当前母片的冻结节点和依赖边传递所需场景锚点，不从可变任务设置或已有资产反向推断创作依赖。
- 没有依赖是明确的空集合，不能因集合为空又退回全片循环场景推断。
- 有依赖时，缺资产、生成器不匹配、未审核等仍需阻断；不能降级为无参考生成。
- 旧调用未传明确依赖范围时保留原有推断行为；不迁移历史任务、不重新编译已付费规格。
- 场景身份仍用于连续性判断。项目现场（site）参考与精确场景参考保留各自职责，不借现场参考强制所有子空间相同站位。
- 原有全任务锚点审核门仍保留；没有场景依赖不等于可以跳过人物审核。
- 不将局部图结构校验描述为完整密码学防篡改证明。

## 验证要求

1. 真实编译、临时数据库物化与适配器执行：合法单场景无锚点依赖时能够通过场景预检。
2. 明确场景依赖缺失或未审核时，在付费生成前仍阻断。
3. 当前母片没有场景依赖时，不因其他母片的循环场景加载额外资产。
4. 精确场景与 site 依赖正确传递；非法键、错连边和畸形冻结输入不默默当成空依赖。
5. 显式空集合与未传参数的旧调用分别回归，保留人物审核和费用保护。

回归入口（已加入 R1 零费用门禁）：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_frozen_scene_dependencies tests.test_production_adapters -v
.\.venv\Scripts\python.exe tests/zero_cost_release_gate.py --level r1
```

这些测试证明依赖传递和预检行为，不证明在线生成质量，也不等同于完整 Worker / 管理台端到端回放。实现与执行状态见 [稳定交付实施记录](stable-delivery-progress.md)。
